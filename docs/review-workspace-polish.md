# Review workspace refinement

Goal: managers can inspect a flag, jump to its passage, and make the alert decision in a calm, coherent workspace rather than a stack of competing controls.

Context: Noah rejected the visual finish of Phase 2 staging at `6841ba7`, asking for Apple-level care and intuitive navigation. This means restraint and consistent behavior, not copying Apple branding. Preserve the locked Pennie system in `.impeccable.md`: PP Mori, light surfaces, beige/navy, blue for interaction, existing spacing/radii.

In scope: presentation and navigation in `AlertReviewDrawer.tsx`, `FullQaRubricReview.tsx`, `TranscriptView.tsx`; corresponding browser checks and synthetic screenshots. Keep the existing two-pane workbench and one audio/draft instance. Keep criterion-level evidence before the decision, with a persistent decision shortcut so managers need not answer optional scores. Surface a guarded Next alert action when a saved review remains in the current queue.

Out of scope: backend/schema, auth, scoring, timestamp alignment changes, transcription requests, reprocessing, dependencies, other pages' redesigns, merge/production deployment.

Done when:
1. Flag actions have one obvious destination, current selection is visible, and mobile returns cleanly between transcript and review.
2. Transcript search/navigation occupies a compact toolbar and highlights complete source text without forced playback scrolling.
3. Decision remains after all saved reasons/evidence, with a direct footer shortcut; optional responses, constraints, saved reviews and draft/error behavior remain.
4. Desktop and 320/375/414/768 layouts are inspected; keyboard, reduced motion, long evidence, missing timestamps and save flows pass real browser checks.
5. Tested, source-pinned screenshots and isolated staging are ready for Noah, with independent review limitations explicit.

Verify: focused recording/workspace/rubric browser tests, typecheck/lint/build, complete `npm run test:browser:ci`, release/staging checks; hosted native playback and no-write review navigation. Stop for production impact, any changed review/data contract, or an unresolved safety issue.

## Design changes

| Before | After | Why |
| --- | --- | --- |
| Large blue audio band competes with evidence | Restrained neutral transport, blue reserved for interaction | Focus belongs to the conversation |
| Separate pill controls and paragraphs above the transcript | Compact search/navigation toolbar, concise status | More readable transcript in the same viewport |
| Repeated Listen + Find + instructional copy | One primary passage action with accessible context | One clear next step |
| Rounded beige cards inside bordered cards | Quieter rows, consistent dividers and spacing | Visual structure without box-on-box noise |
| Generic Continue review action | Direct Your decision shortcut; Next alert after a clean saved review | Managers need not fill optional scores or rediscover navigation |

Independent design review caught that moving the entire scorecard would also move criterion-level evidence after the decision. That proposal was dropped: all evidence stays before the verdict. Existing automatic progression when a save leaves the filtered queue is unchanged. The new footer Next action is only for a saved, clean review that remains in the queue.

The toolbar is now sticky only in unconstrained drawer transcripts; Call Detail has a static toolbar and a browser regression check. The count follows the displayed set and describes criteria, not required responses. Final static re-review found no remaining actionable issues.
